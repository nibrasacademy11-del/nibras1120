# خطة تطوير نظام إدارة أكاديمية نبراس

> الحالة: **مسودة للاعتماد** — 2026-11-10
> نسخة الكود القديم محفوظة قبل أي تعديل (التفاصيل في آخر الملف).

## القرارات المعتمدة

| الموضوع | القرار |
|---|---|
| الاستضافة | نفضل على **Vercel + MongoDB Atlas** (نفس قاعدة البيانات المركزية) |
| قاعدة التجربة | **Atlas مجانية منفصلة (M0)** للتطوير والتجربة، ومفيش أي تجربة على القاعدة الحقيقية |
| الواجهات | الموقع العام يفضل زي ما هو، والبوابات الأربع تتبني **React + Vite** تحت `/portal` |
| العملة الأساسية | **SAR ريال سعودي** |

## ١. الوضع الحالي (نقطة البداية)

النظام الحالي موقع تعريفي + كتالوج برامج + لوحة إدارة بسيطة:

- **المستخدمين** `User`: اسم وإيميل وتليفون، والأدوار `student / user / admin` بس.
- **البرامج** `Course`: كتالوج ثنائي اللغة، بسعر وخصم، والعملة الافتراضية US$. مفيش محاور.
- **الطلبات** `Inquiry`: استفسارات وطلبات تسجيل من السلة، بحالات بسيطة.
- **الشهادات** `Certificate`: رقم شهادة + PDF مرفوع يدوياً + صفحة تحقق عامة.
- **محتوى الموقع** `SiteSettings`, `Testimonial`, `Media`.
- الحماية الموجودة: JWT في Cookie، rate limit، التحقق من الدور على السيرفر.

مفيش حالياً: موظفين، فرق، CRM، تسجيلات، مدفوعات، عمولات، حضور، صلاحيات تفصيلية، سجل عمليات.
يعني أغلب المطلوب **إضافة** جديدة فوق النظام، مع ترحيل البيانات الحالية من غير ما نكسر الموقع.

## ٢. قيود Vercel وإزاي هنتعامل معاها

| القيد | الحل |
|---|---|
| حجم أي طلب أقصاه 4.5MB | المستندات والمرفقات ترفع **مباشرة** لمساحة تخزين سحابية (Cloudflare R2 أو Vercel Blob) بروابط موقعة مؤقتة |
| مفيش سيرفر شغال طول الوقت | التذكيرات وانتهاء التصاريح وإقفال الفترات عن طريق **Vercel Cron** |
| مدة تنفيذ الدالة محدودة | التقارير الكبيرة تتقسم صفحات، والتصدير على دفعات |
| توليد PDF بالعربي | التقارير: محرك طباعة المتصفح بتنسيق A4 (أفضل دعم للعربي وRTL). الشهادات والإيصالات: توليد على السيرفر بـ Chromium خفيف |
| النسخ الاحتياطي | نسخة يومية تلقائية من القاعدة (mongodump) لمساحة التخزين عن طريق GitHub Actions، بالإضافة لنسخ Atlas لو الباقة تسمح |
| الحضور بدون إنترنت | جهاز صغير داخل الأكاديمية (Local Server) — ده منفصل عن Vercel في كل الأحوال |
| الاستخدام التجاري | Vercel بتشترط باقة **Pro** للاستخدام التجاري (حوالي 20$ شهرياً) |

## ٣. قواعد ثابتة في كل المراحل

1. **الصلاحيات على مستوى البيانات**: كل استعلام على السيرفر يتفلتر حسب المستخدم (بياناتي / فريقي / الكل). إخفاء الزرار في الواجهة مش حماية.
2. **سجل عمليات Audit Log** غير قابل للتعديل لكل إنشاء وتعديل وأرشفة واعتماد وتصدير ودخول.
3. **ممنوع الحذف النهائي** للسجلات المالية والشهادات والتسجيلات — أرشفة فقط، والتصحيح يكون بقيد تسوية موثق بسبب.
4. **منع تضارب التعديلات**: كل سجل له رقم إصدار، ولو اتنين عدلوا نفس السجل التاني ياخد تنبيه بدل ما يمسح شغل الأول.
5. **تشفير البيانات الحساسة** (رقم الهوية والجواز) داخل القاعدة، مع إمكانية البحث بيها من غير فك التشفير.
6. **الأرقام التسلسلية** (Customer ID، رقم الإيصال، رقم الشهادة) تتولد من السيرفر بعداد مضمون من غير تكرار.
7. **كل مرحلة**: تتطور وتتجرب على القاعدة التجريبية ← رابط Preview على Vercel تراجعه ← بعد موافقتك نسخة احتياطية من القاعدة الحقيقية ← ترحيل البيانات ← النشر. الـ API القديم يفضل شغال لحد ما الجديد يحل محله.
8. **اختبارات تلقائية** للصلاحيات والحسابات المالية والعمولات قبل أي نشر.

## ٤. مراحل التنفيذ

### المرحلة ٠ — الأساس (مفيش تغيير ظاهر للزوار) — ✅ الكود جاهز على فرع `erp-phase-0`، مستني قاعدة التجربة للاختبار الكامل
- قاعدة Atlas تجريبية + بيانات وهمية للتجربة + ملف `.env.development`.
- إعادة تنظيم الـ Backend في وحدات (crm, hr, finance, ...) مع بقاء المسارات الحالية شغالة.
- **محرك الصلاحيات**: الأدوار التسعة (Super Admin, Admin, HR Manager, Finance Manager, Team Leader, Employee, Accountant, Customer Support, Customer) وصلاحيات (مشاهدة، إنشاء، تعديل، أرشفة، اعتماد، تصدير، طباعة، إدارة الصلاحيات) قابلة للتعديل من الإدارة.
- سجل العمليات، العدادات التسلسلية، تشفير الحقول الحساسة.
- **الأمان**: Two-Factor (تطبيق Google Authenticator) إجباري للإدارة واختياري للباقي، سجل محاولات الدخول، إدارة الجلسات والأجهزة وإنهاؤها.
- هيكل بوابات React: تسجيل دخول موحد، عربي/إنجليزي، RTL/LTR، قوائم حسب الدور، تصميم متجاوب للموبايل.

### المرحلة ١ — الموظفين والفرق + CRM + البحث + طلبات التصريح — ✅ الكود جاهز على فرع `erp-phase-1`، مستني قاعدة التجربة للاختبار الكامل
- **HR**: ملف لكل موظف، الأقسام، الفرق، Team Leader، سجل نقل الموظف بين الفرق، تعطيل الحساب ونقل عملائه لموظف تاني مع الاحتفاظ بالتاريخ.
- **ملف العميل**: Customer ID تلقائي + رقم داخلي ثابت، الهوية والتواصل والدولة، تاريخ ومصدر التسجيل، منشئ الملف، المسؤول الرئيسي، الفريق، التصنيفات والشرائح، حالة العميل (Lead ← مهتم ← عميل ← مفقود + سبب الخسارة).
- **السجل الزمني**، الملاحظات الداخلية، سجل التواصل (مكالمات/واتساب/إيميل)، المتابعات والتذكيرات، المهام، الإشعارات داخل النظام.
- **اكتشاف التكرار** (بالتليفون والإيميل ورقم الهوية) و**الدمج الآمن** مع الاحتفاظ بتاريخ الملفين.
- **توزيع العملاء** على الموظفين و**نقل العميل** بين الموظفين بسجل كامل.
- **المستندات**: رفع مع الاحتفاظ بالإصدارات السابقة، وتحميل بروابط مؤقتة حسب الصلاحية.
- **البحث** برقم العميل أو الهوية أو الجواز: الموظف غير المسؤول يشوف كارت محدود بس (الرقم، الاسم حسب السياسة، المسؤول، البرنامج، المحاور، حالة التسجيل)، ورقم الهوية مخفي جزئياً.
- **طلب التصريح Access Request**: يختار الموظف نوع البيانات (تواصل / هوية / مالي / مستندات / ملاحظات) والغرض والمدة ← يوصل للمسؤول الرئيسي (أو الأدمن) ← موافقة أو رفض ← يظهر المطلوب بس لحد انتهاء المدة ← يمكن الإلغاء في أي وقت ← كله في السجل.
- **ترحيل البيانات الحالية**: المستخدمين بدور student/user يتحولوا لعملاء، الاستفسارات وطلبات التسجيل تتحول Leads مربوطة بيهم، والشهادات الحالية تتربط بأصحابها. أول تشغيل يكون تجربة بتقرير من غير كتابة.
- لوحة تحكم أولية للموظف والـ Team Leader.

### المرحلة ٢ — البرامج والمحاور والتسجيلات — ✅ الكود جاهز على فرع `erp-phase-2`، مستني قاعدة التجربة للاختبار الكامل
- البرامج الحالية تفضل هي الكتالوج، ويتضاف لكل برنامج **محاور** بعدد تحدده الإدارة، لكل محور محتوى ومتطلبات وترتيب.
- **التسجيل**: عميل × برنامج، له مسؤول ومدفوعات ومحاور وشهادات مستقلة. العميل الواحد ممكن يكون عنده أكتر من تسجيل.
- **حالة كل محور**: Not Started ← In Progress ← Ready for Review ← Approved / Rejected ← Certificate Issued، مع مراجعة الموظف والـ TL واعتماد الأدمن النهائي وتسجيل سبب الرفض.
- التسجيل المستمر من غير دفعات سنوية ثابتة، والمجموعات التدريبية.
- **بوابة العميل**: برامجي، المحاور ونسبة التقدم.

### المرحلة ٣ — النظام المالي متعدد العملات — ✅ الكود جاهز على فرع `erp-phase-3`، مستني قاعدة التجربة للاختبار الكامل
- العملات: الأساسية SAR، إضافة وتعطيل (EGP, SAR, AED, USD, EUR, KWD...)، أسعار صرف بتاريخ ووقت مع الاحتفاظ بتاريخ التغييرات.
- كل دفعة تتحفظ **بعملتها الأصلية + سعر الصرف وقت التحصيل + المقابل بالريال**، وتغيير السعر بعد كده مش بيأثر على القديم.
- الدفع الكامل والجزئي، **خطط الأقساط** وجدولها، الخصومات (بموافقة)، **الاستردادات** المربوطة بالدفعة الأصلية، **إيصالات** برقم تسلسلي وPDF.
- الخزائن والحسابات البنكية والمحافظ الإلكترونية، التحويلات بينها، الأرصدة، المصروفات.
- **دفتر قيود ثابت**: أي عملية مالية قيد لا يتعدل؛ التصحيح بقيد تسوية بسبب. **إقفال الفترات المالية** بعد اعتمادها.
- كشف حساب العميل، وطلبات الموافقة على الخصم والاسترداد والتعديل.
- بوابة الدفع الإلكتروني: تجهيز النظام لها، وربطها فعلياً عند الحاجة.

### المرحلة ٤ — محرك العمولات — ✅ الكود جاهز على فرع `erp-phase-4`، مستني قاعدة التجربة للاختبار الكامل
- العمولة على **المحصّل فعلياً** بس، وتتحسب على مستوى التسجيل والدفعة.
- نسبة لكل موظف، عمولة إضافية للـ TL، توزيع عمولة العميل على أكتر من مستفيد بنسب تحددها الإدارة.
- النسب **تتجمد وقت استحقاق كل دفعة**، والاسترداد يعكس العمولة المرتبطة بيه تلقائياً.
- الحالات: مستحقة ← معتمدة ← مصروفة، مع كشف شهري تفصيلي لكل موظف وTL وسجل تعديل النسب.

### المرحلة ٥ — الشهادات والاعتمادات
- قوالب قابلة للتخصيص بشعار الأكاديمية والاعتمادات: شهادة لكل محور + شهادة نهائية للبرنامج بعد استيفاء شروطه.
- PDF عالي الجودة A4، رقم فريد، **QR** يفتح صفحة التحقق العامة (تطوير صفحة verify الحالية).
- **منع تكرار** نفس الشهادة لنفس المحور ونفس التسجيل.
- إلغاء وإعادة إصدار مع الاحتفاظ بكل الإصدارات، والتحميل من حساب العميل.
- الشهادات القديمة المرفوعة يدوياً تفضل شغالة وقابلة للتحقق.

### المرحلة ٦ — التقارير والطباعة والتحليلات ولوحات التحكم وإضافات CRM
- **كل شاشة قائمة أو سجل** فيها: طباعة / PDF A4 / Excel، والسيرفر بيرجع بس البيانات المسموح بيها، وكل تصدير بيتسجل.
- مواصفات PDF: A4، شعار، اسم التقرير، تاريخ الاستخراج، ترقيم صفحات، رأس الجدول يتكرر في كل صفحة، الصف ما يتقسمش بين صفحتين، عربي RTL وإنجليزي LTR.
- التقارير المطلوبة كلها (موظفين، حضور، عملاء، برامج ومحاور، تسجيلات، شهادات، مدفوعات وأقساط، كشوف حسابات، إيرادات ومصروفات، عمولات، أداء الفرق، مهام، شكاوى، سجل العمليات) بفلاتر التاريخ والموظف والعميل والبرنامج والقسم والحالة.
- **مؤشرات الإدارة**: عملاء جدد، تسجيلات، حسب الدولة والمصدر، نسب التحويل من Lead لعميل، أداء الموظفين والفرق، البرامج الأكثر تسجيلاً، المحاور المكتملة والمعلقة، التحصيل حسب العملة، المتبقي، الاستردادات، العمولات، عملاء بدون متابعة، أسباب الخسارة.
- لوحات التحكم النهائية: Admin, Employee, Team Leader, Customer.
- **الشكاوى**، **قياس رضا العملاء**، تحليل العملاء المفقودين.

### المرحلة ٧ — الحضور والانصراف
- شاشة في الاستقبال بتعرض **QR بيتغير كل 30 ثانية**، والموظف يمسحه من الموبايل وهو داخل على البوابة.
- مواعيد الدوام، التأخير والغياب وساعات العمل، طلبات الإجازة والاستئذان بموافقات، مين موجود دلوقتي، تقارير شهرية.
- **Local Server** على جهاز صغير داخل الأكاديمية: يشتغل على الشبكة الداخلية لما النت يقطع، ويزامن تلقائياً مع السحابة لما يرجع من غير تكرار.

### المرحلة ٨ — التسليم: الاختبار الشامل والمراقبة وتطبيق Electron
- اختبار كل السيناريوهات (صلاحيات، تحايل عن طريق الـ API والروابط المباشرة، مالي، عمولات، شهادات).
- النسخ الاحتياطي اليومي + تجربة استعادة فعلية موثقة.
- المراقبة: تتبع الأخطاء (Sentry) + مراقبة توقف الموقع.
- **تطبيق Desktop بـ Electron** لبوابة الإدارة فقط: نفس الـ Backend والبيانات والصلاحيات، مع تحديث تلقائي.
